# AGENTS.md

How work is done in this repository, for coding agents and for people. Claude Code reads this file because the
repository has no `CLAUDE.md`: "By default, Claude reads `AGENTS.md` only when you have no `CLAUDE.md` in your
working directory or above it", and "Reading `AGENTS.md` directly requires Claude Code v2.1.277 or later"
([Claude Code memory docs](https://code.claude.com/docs/en/memory), read 2026-11-14). It stays short because it
is loaded into every session.

## Map

- `src/tools/` - the seven tools: NHTSA's VIN decoder, model list, recalls, complaints and safety ratings
  (`nhtsa.ts`), the fictional catalog (`catalog.ts`), the handoff (`handoff.ts`); `http.ts` is the only place
  that reaches the network, `recorded.ts` answers from the recordings instead.
- `src/guards/rules.ts` - the six rules every answer is checked against. The core of the product.
- `src/agent/` - the loop (`loop.ts`), the system prompt, the `submit_answer` schema, the Anthropic adapter,
  prices per model (`cost.ts`).
- `src/server/` - one live chat request with no AWS in it: limits, Turnstile, the order of refusals.
- `src/lambda/` - the AWS Lambda glue: Parameter Store, DynamoDB counters, the streamed response.
- `src/cli/ask.ts` - run any tool from a terminal, with or without the network.
- `src/evals/` - the eval cases' loader, the graders (`grade.ts`), the recordings with a planted complaint
  (`fixtures.ts`), and the pure parts of the subscription runner (`claude-cli.ts`).
- `src/mcp/` - the agent's tools as an MCP server over stdio (`server.ts`), one conversation's tool handlers with
  `submit_answer` checked by the same rules (`session.ts`), and how to start it (`server-command.ts`). Built for
  the eval runner.
- `evals/` - the 50 eval cases (`cases.json`) and partial runs (`results/`); a complete run goes to
  `web/src/evals/`, where the Evals tab reads it. Three complete runs are there (Haiku 5.5, Sonnet 5.5, Opus 5.5,
  2026-11-14).
- `web/` - the page (React, Vite): the desk (Ask, Examples, Evals) and the system map in twelve layouts.
  `web/src/studio/` - the 12 layouts, 21 colour sets and 15 typefaces (`presets.ts`, with the default), the
  visitor's choice, the theme, the boot script and the Studio panel; `web/src/rich/` - the four section-built
  layouts (01, 04 to 06); `web/src/simple/` - the three one-column ones (07 to 09); `web/src/looks/` - the five
  map-first ones (10 to 14, `LookPage.tsx` and `looks.css`); `web/src/system-map.ts` - the map's graph and which
  piece each event lights, pure and tested; `web/src/map-feed.ts` - hands the map the run that is playing;
  `web/src/shared/` - the map's drawing (`SystemMap.tsx`, `map.css`), "How it works" with the dot field's mark
  sizes (`field.ts`), and "How it was built"; `web/src/site-data.json` - every number the page shows;
  `web/src/replays/` - the recorded runs.
- `fixtures/nhtsa/` - recorded NHTSA replies with their dates in `manifest.json`. `data/catalog.json` - the
  invented catalog, generated by `scripts/build-catalog.ts`.
- `scripts/` - record fixtures, build the catalog, record replays, one live run, bundle the Lambda;
  `eval-subscription.ts` runs the eval cases through Claude Code on a subscription login; `export-site.ts` writes
  `web/src/site-data.json`.
- `test/` - `node --test` files, one per unit, plus the page and bundle builds.
- `docs/decisions/` - why things are the way they are, each with its sources and measurements.

## Checks (none calls a model)

```bash
npm test               # node --test on test/**/*.test.ts, recordings only (230 tests in 39 files on 2026-11-14)
npm run web:build      # the page
npm run build:lambda   # dist/lambda/index.mjs
```

After a change to the tests, the recorded runs, the agent's tools or limits, the rules or the decision records,
refresh the page's numbers. The export runs the test suite first and refuses while any test fails:

```bash
node --experimental-strip-types --disable-warning=ExperimentalWarning scripts/export-site.ts   # npm run site:export
```

CI runs the first three; it does not run the export or any eval.

## Rules

1. **Test first, and watch it fail.** Write the test, run it, and see it fail on the old code for the reason you
   expect before writing the fix. A test that passes on the old code proves nothing about the change. Example: the
   "Ranger trucks" coverage test in [test/rule-applicability.test.ts](test/rule-applicability.test.ts) first used
   a recall that also says "Ranger vehicles", passed on the old code, and was switched to 17V787000, which then
   failed as it should ([README, What failed](README.md#what-failed-and-what-fixed-it)).
2. **The code rules are the product.** [src/guards/rules.ts](src/guards/rules.ts) decides what a customer sees;
   the prompt only explains it. Never delete or loosen a rule or its assertion to make a run pass, never paste a
   computed value in as the expected one. A new kind of claim the agent can make gets a field in
   `submit_answer` ([src/agent/answer-schema.ts](src/agent/answer-schema.ts)) and a rule that checks it against
   what a tool returned in the same run.
3. **Tests use the recordings, never the network.** Tools take an injected `fetchJson`
   ([src/tools/http.ts](src/tools/http.ts)); tests hand them [src/tools/recorded.ts](src/tools/recorded.ts),
   where an unrecorded URL is an error, not a fall-through to the live API. Re-recording
   (`npm run fixtures:refresh`) is a change of its own, because NHTSA adds recalls and a moved result has to mean
   the agent changed, not the data ([decision 0003](docs/decisions/0003-recorded-nhtsa-fixtures.md)).
4. **Never `ANTHROPIC_API_KEY`.** The development key lives in a git-ignored `.env.local` under
   `RECALL_DESK_ANTHROPIC_KEY`, and the adapter is handed the key explicitly
   ([src/agent/anthropic.ts](src/agent/anthropic.ts)). The standard name would also switch a Claude Code
   subscription login on the same machine to paid per-token billing. The live key exists only in Parameter
   Store. Eval runs never get a key at all: they go through Claude Code on a claude.ai login, and the runner strips
   every `ANTHROPIC_*` variable from the child process ([src/evals/claude-cli.ts](src/evals/claude-cli.ts)). See
   [.gitignore](.gitignore) and [SECURITY.md](SECURITY.md).
5. **Ask a person before anything that spends money, deploys or cannot be undone:** `npm run live:run`, an eval
   run beyond the 3 smoke cases (it uses the subscription's plan limits), a recording refresh that changes
   results, a deploy, a change to the limits or the budget
   ([src/server/limits.ts](src/server/limits.ts)), a force-push.
6. **No real retailer's name, logo, part numbers or prices, anywhere.** The store is "Auto Parts Store"
   ([src/config.ts](src/config.ts)) and the catalog is invented. Makes and models are real because NHTSA's data is.
7. **Say whether a number was measured or inferred.** Every number carries its n or its derivation; an
   explanation without a measurement says it is inferred. Example: the
   [Results](README.md#results) give mean and median cost with n=6 and call the daily-budget arithmetic derived.
8. **Ground a decision in the provider's documentation, then measure it.** Quote the line, with the date read, in
   [docs/decisions/](docs/decisions/). Example: [0002](docs/decisions/0002-strict-submit-answer-checked-by-code.md)
   quotes Anthropic's docs on forced tool use before relying on a strict tool instead.
9. **Plain words.** Hyphens with spaces (" - "), never em dashes; no exclamation marks; third person in the docs.
10. **Smallest change that solves it.** Extend what exists before adding a layer or a dependency: the Lambda
    bundle uses Rolldown because Vite already installed it ([scripts/build-lambda.ts](scripts/build-lambda.ts)).
11. **Check what a push publishes.** The repository is public. Before every push, scan the added lines for
    key-shaped strings, personal data and infrastructure details such as account ids, bucket or distribution ids.
    The infrastructure code stays in a private repository for that reason ([docs/DEPLOY.md](docs/DEPLOY.md)).
12. **Commit messages carry the reasoning:** the symptom, the root cause (file, line or setting), why this fix over
    the obvious alternative, the evidence (numbers before and after), and what is still unverified.
